# 📊 benchmark — 성능·정확도·신뢰성 측정 체계

이 디렉터리는 **DFIR Triage 자동화 파이프라인(01~07단계)의 분석 품질과 성능을 객관적으로 측정하고 검증**하기 위한 독립 평가 계층입니다. `src/` 내부 코드를 몰라도 독립된 CLI 도구만으로 시스템의 성능을 측정할 수 있습니다.

---

## 📁 1. 디렉터리 구조 및 역할

```text
benchmark/
├── README.md                  # [본 문서] 벤치마크 가이드
├── collect.py                 # [결과 집계] 누적된 실행 결과를 한눈에 표로 출력
├── evaluate.py                # [정밀 채점] 정답 대비 공격 기법/아티팩트 재현율(Recall) 측정
├── validator_check.py         # [검증기 테스트] 06단계 검증기가 정상 문장을 기각하지 않는지 확인
├── ground_truth_schema.json   # 정답 데이터셋 규격 스키마
│
├── datasets/<케이스ID>/        # [평가 대상] 공식 입력(input.json)과 정답 기준(ground_truth.json)
├── fixtures/<케이스ID>/        # [고정 입력] 사람이 작성한 입력 및 LLM 스텁 응답 (⚠️ 수정 금지)
├── golden/<케이스ID>/          # [모범 답안] 코드가 정상일 때의 기대 출력 (로직 변경 시 갱신)
├── validator/                 # [검증기 케이스] 검증기 회귀 테스트용 데이터
└── results/                   # [실험 로그] live_check 실행 시 자동 저장되는 기록 (git 제외)
```

### 💡 핵심 규칙: `fixtures/` vs `golden/` 차이점

- **`fixtures/` (절대 수정 금지)**: 사람이 직접 작성한 불변의 테스트 입력 데이터입니다.
- **`golden/` (모범 답안)**: 파이프라인 로직을 개선했을 때 비교 기준이 되는 정답 출력 파일입니다.

## 🚀 2. 바로 쓰는 실전 명령어 (Quick Start)

### ① 전체 실험 결과 한눈에 보기

`results/`에 누적된 실물 관통 실행 기록을 종합 성적표로 출력합니다.

```bash
.venv/Scripts/python.exe benchmark/collect.py
```

### ② 정답 대비 재현율(Recall) 채점

특정 시나리오의 정답과 비교하여 기법/아티팩트를 얼마나 잘 찾았는지 채점합니다.

```bash
.venv/Scripts/python.exe benchmark/evaluate.py --dataset benchmark/datasets/C-001-webshell
```

### ③ 검증기(06단계) 오탐 확인

검증기가 너무 엄격해서 정상적인 AI 소견을 억울하게 기각하지 않는지 점검합니다.

```bash
.venv/Scripts/python.exe benchmark/validator_check.py
```

### ④ 60GB 실물 디스크 + 실제 AI 실전 관통

스텁 없이 60GB 디스크 이미지와 AI 모델로 01→07 전 과정을 실전 실행합니다.

```powershell
.venv/Scripts/python.exe tools/live_check.py `
  --case-id MY-TEST-01 `
  --evidence evidence/win10_sysmon_testimage.001 `
  --volume 1 `
  --model qwen2.5:latest `
  --raw "키오스크 단말기에 비인가 USB를 삽입한 후 수상한 서비스가 설치되고 실행된 정황..." `
  --force
```

## 📈 3. 측정 지표 및 평가 체계

### 🌟 3대 핵심 기본 지표 (측정 대상)

| 지표                          | 정의                                               | 산출 도구     |       현재 관측값        |
| ----------------------------- | -------------------------------------------------- | ------------- | :----------------------: |
| **1. 재현율 (Recall)**        | 정답 필수 증거와 공격 기법을 빠짐없이 선별했는가?  | `evaluate.py` | **100.0% (⚠️ 자기채점)** |
| **2. 환각률 (Hallucination)** | AI 소견 중 증거와 불일치해 기각된 비율 (측정 대상) | `collect.py`  |    **0.0% ~ 100.0%**     |
| **3. 소요 시간 (Efficiency)** | 01~07 전 단계 및 AI 추론에 걸린 시간               | `collect.py`  |  **약 40초 ~ 117초**<br>(완주한 실행 기준)  |

> ⚠️ **환각률과 재현율은 '달성할 목표치'가 아닌 '측정 대상'입니다.** 인위적으로 0%나 100%를 강제하면 검증기를 느슨하게 만드는 통계적 왜곡이 발생합니다.

### 🔬 상세/확장 분석 지표 예시

1. **증거 깔때기 (Evidence Funnel)**:
   - 정답 증거의 누락 단계 추적 (`파싱 ➡️ 전달 ➡️ 인용 ➡️ 검증통과`).
2. **증거 압축률 (Triage Filtering Ratio)**:
   - 60GB 디스크 수만 건 중 핵심 60건 선별 (`98.2% ~ 99.7%` 노이즈 압축).
   - _(※ 압축률은 1건만 보내도 99.9%가 되므로, 반드시 **재현율과 짝으로 평가**해야 함)_
3. **검증 통과율 (Verification Pass Rate)**:
   - AI 소견 중 04 파싱 레코드 필드 대조를 통과한 **유효 소견(Confirmed Findings) 비율**.
4. **자원 효율성 (Resource Footprint)**:
   - GPU VRAM 점유율 및 초당 토큰 생성 속도(tok/s).

## 🧭 5. 다중 시나리오 및 로컬 LLM A/B 테스트 주의사항

- **시나리오 비교 (예시, 키오스크 단말 침해 vs 관리 서버 침투/횡적이동)**:
  - 공격 벡터(USB/악성서비스 vs 네트워크/권한상승)가 바뀔 때 파이프라인의 선별/파싱 정확도를 입증하는 가장 좋은 방법입니다.
- **로컬 LLM 모델 비교 (예시, 7B vs 14B vs Llama3)**:
  - **VRAM 주의 (8GB 환경)**: `7B (5GB)`는 100% GPU로 완주(1분 30초)하지만, `14B (15GB)`는 CPU 오프로딩으로 매우 느립니다.
  - 하드웨어 한계로 인한 속도 저하를 모델 자체의 성능 차이로 오독하지 않도록, 동일한 VRAM 적재 조건에서 공정하게 비교해야 합니다.
