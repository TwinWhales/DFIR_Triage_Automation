# 폐쇄망 환경을 위한 DFIR 초기 분석 AI 에이전트 개발

## 1. 프로젝트 목표

- 침해사고 문제 상황(시나리오) 및 아티팩트 제시 시, LLM 기반 에이전트가 적절한 초기 단계(Triage) 분석을 자동으로 수행
에이전트의 상황 판단, 도구 선택, 분석 과정을 상세히 기록하여 추후 분석가의 정밀 분석 및 최종 보고서 작성의 기초 자료로 활용

## 2. 핵심 요구사항

- 상황 맞춤형 도구 제어: 주어진 파일 포맷(네트워크 패킷, 메모리 덤프, 윈도우/리눅스/안드로이드 이벤트 로그 등)을 식별하고 올바른 분석 도구를 자율적으로 선택 및 실행.
- 오프라인 자가 조치: 외부 네트워크(API) 연결 없이 내부 자원만으로 동작. 필수 도구가 없을 경우 자체적으로 설치를 시도하되, 설치 전 반드시 CLI 상에서 분석가의 승인을 받도록 구현.
- 신뢰성 확보 (환각 통제): AI의 추론 결과에 대한 신뢰도(Confidence)를 수치화. 결과 도출 시 반드시 추출된 로그나 아티팩트의 명확한 근거(Grounding)를 기반으로 작성. 특히 sLLM의 환각 방지를 위해 Structured Output을 활용하여 '파일명, EventID, 로그 원문' 등 명확한 출처(Reference) 생성을 강제화.
- 위협 인텔리전스 맵핑: 사전 학습되거나 로컬에 구축된 MITRE ATT&CK 지식 기반을 활용하여, 분석된 위협 행위를 적절한 T-Code(Tactic & Technique)로 맵핑.

## 3. 입출력 및 워크스페이스 명세

- 입력 (Input): 사용자가 CLI를 통해 침해사고 시나리오(일반 자연어 텍스트)와 분석 대상 파일의 경로를 입력. 입력된 자연어 시나리오는 내부 전처리 LLM 노드를 통해 핵심 지표(초기 IoC, 분석 타임라인 등)로 자동 추출 및 구조화되어 타겟 분석의 기준점으로 활용됨.
- 격리된 워크스페이스: 에이전트 구동 시 타겟 아티팩트별로 별도의 전용 작업 폴더(Workspace)를 자동 생성하며, 도구가 분석해 낸 모든 중간 결과물(추출된 문자열, 파싱된 로그 등)은 해당 폴더에 모아서 저장.
- 최종 산출물 (Output):
  - 시간 분석 기록 (CSV): AI가 수행한 모든 작업(도구 실행, 타임스탬프, 발생한 에러 등)을 타임라인 형태로 기록.
  - 초기 요약 보고서 (Markdown): 에이전트가 파악한 핵심 침해 지표(IoC), 공격 흐름, MITRE ATT&CK 맵핑 결과가 포함된 트리아지 리포트.

## 4. 보안 및 하드웨어 제약사항

- 포렌식 무결성 (Read-Only): 에이전트 및 연동된 모든 분석 도구는 원본 아티팩트 파일에 대해 철저히 읽기 전용(Read-only)으로만 접근하여 증거의 무결성을 훼손하지 않음.
- 구동 환경: 최신형 일반 업무용/개발용 노트북 환경에서 구동 가능하도록 최적화. (VRAM 제약을 고려하여 양자화된 로컬 소형 모델(sLLM) 활용).

## 5. 고도화 및 다중 프레임워크 개발 전략

- ReAct 및 Function Calling: 에이전트가 스스로 논리적 단계를 고민하고(Thought), 알맞은 도구를 선택해 명령어를 조립(Action)하며, 결과를 바탕으로 다음 행동을 결정하는 구조 채택.
- 컨텍스트 윈도우 조절 및 정규화: 대용량 파일 분석 시 모델 메모리 초과를 방지하기 위해, 원본을 직접 읽지 않고 CLI 도구로 1차 파싱을 수행. 또한 도구별로 상이한 출력 결과(Text, CSV 등)는 Python 래퍼(Wrapper) 레이어를 거쳐 표준화된 JSON 형태로 변환한 뒤 LLM에 전달하여 토큰 낭비를 막고 파싱 정확도를 극대화.
- 확장 가능한 아키텍처: 초기 개발은 상태 통제와 기록에 유리한 LangGraph를 메인으로 사용하여 뼈대를 구축. 향후 로그 검색 및 보고서 작성의 고도화를 위해 LlamaIndex, CrewAI 등을 플러그인처럼 연동할 수 있도록 모듈화 설계 지향.

## 6. 테스트 및 검증 방안 (KPI)

- 검증 데이터셋: Hack The Box (HTB) Sherlock 플랫폼의 공인된 DFIR 시나리오 문제(PCAP, EVTX 분석 등)를 에이전트에게 입력.
- 성공 기준: 에이전트가 도출한 초기 분석 요약 보고서와 HTB Sherlock 문제의 실제 정답(Flag 및 침해 경로)을 대조하여 분석의 정확성과 도구 활용의 적절성을 평가.
